Get started Journeys CLI
Screenshots · Accessibility · Web Vitals · Link checks · HAR

Drive Chrome from .NET. Share the journeys.

A small DevTools Protocol client with no dependencies beyond the BCL, and synthetic journeys: plain text files in agent-browser's command language that replay in agent-browser, in dotnet test, on Playwright and Elastic Synthetics, and from the cdp command line. Screenshots, accessibility audits, Web Vitals, link checks and HAR recording are one line each.

Small, direct, safe to share

Talking the DevTools Protocol directly means no Node, no daemon and no third party's output format in the way: one web socket to Chrome, from your process.

no dependencies
The BCL and a web socket

Launch or connect to Chrome, isolated contexts per caller, flattened sessions on one socket, lock-free reply routing. AOT and trim clean.
agent-browser's language
Explore with an agent, keep the journey

One command per line, written as agent-browser writes it. Export any journey to agent-browser batch JSON and it runs there unchanged.
safe by default
A shared journey stays in its lane

An allow list on every request, popups included. Secrets by $env: reference and redacted. Page output fenced for agents.
waits like a user
Locators that wait, input that is real

Role, text, label, placeholder, alt, title, test id and CSS. Every action waits for a visible, enabled element and for the navigation it starts.
native AOT
A CLI that starts instantly

cdp run, check, batch, snapshot and screenshot, native on Linux, macOS and Windows. A 40-step journey runs in about a second, Chrome's start included.
snapshots
Journeys as snapshot tests

Nullean.Snapshots runs a journey in dotnet test and compares every checkpoint as a tree, so a failure names what moved.

The journey language

A subset of agent-browser's commands: everything a repeatable test needs, nothing that reaches outside the page it tests.

GroupCommandsWhat they do
Navigateopen, back, forward, reloadrelative URLs resolve against the base URL; each waits for load
Actclick, fill, type, press, check, select, drag, upload, …real mouse and keyboard input, after waiting for the element
Findfind role|text|label|… [action] --nameagent-browser's semantic locators, no run-specific refs
Wait and setwait, set viewport|media|device|offline|headers|credentialsfor an element, text, URL or load state; emulation and headers
Readsnapshot, get, is, console, errorscheckpoints: their output is the journey's transcript
Checka11y, links, network requests --failed, timings, vitalslists by default, --strict or --budget to fail the step
Recordscreenshot, network har start|stopfiles into the artifacts folder the host chose, nowhere else

A library first

Everything a journey does is a method: launch, contexts, locators, reads and checks. page.SendAsync reaches any DevTools command the library does not wrap.

● ● ●install
dotnet add package Nullean.Cdp
dotnet add package Nullean.Cdp.Journeys
dotnet tool install --global Nullean.Cdp.Cli
# or, without installing:
dnx Nullean.Cdp.Cli chrome
● ● ●Program.cs
await using var browser = await Browser.LaunchAsync();
await using var context = await browser.NewContextAsync();
var page = await context.NewPageAsync();
await page.GotoAsync("http://localhost:5000/");

await page.Label("Search").FillAsync("lamp");
await page.Role("button", "Go").ClickAsync();
Console.Write(await page.SnapshotAsync(new() { Compact = true }));

var problems = await page.AuditAsync();
var vitals = await page.VitalsAsync();

Also on Playwright and Elastic Synthetics

The same journey file runs as a step-by-step Playwright Test or as a Synthetics browser monitor, through the @nullean/journeys npm package. Its parser is tested against the .NET one, so a journey that parses here parses there. What is the same, and what is not

● ● ●install
npm install @nullean/journeys
● ● ●checkout.journey.ts
import { journey, step } from '@elastic/synthetics';
import { journeySteps } from '@nullean/journeys/synthetics';

journey('checkout', ({ page, params }) =>
  journeySteps({ page, step, params }, `
    open /
    find label Search fill lamp
    find role button click --name Search --exact
    get text #count
  `, { baseUrl: params.url }));
